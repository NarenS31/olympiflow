# The learned semantic graph, read out of the checkpoint

**Status: EXPLORATORY.** No GNN solves, no explainer, no LLM. `A_sem` is a
stored parameter, so everything here is a static read plus arithmetic and is
exactly reproducible from the checkpoint files alone.

This is the companion to the explainer analysis. Where that asks *what does the
explainer say the model leans on*, this asks *what does the model's own learned
graph look like* — a question that needs no solves at all.

## 1. What the object is

`XTrafficSTGNN` blends two graphs into its first support (`stgnn.py:261-268`):

```
A_final = sigmoid(alpha) * A_phys + (1 - sigmoid(alpha)) * A_sem
A_sem   = softmax(relu(E @ E.T), dim=1),   E = sem_embed [N, embed_dim]
```

| Property | Value |
|---|---|
| Parameterisation | `A_sem = softmax(relu(E @ E.T), dim=1) with E = sem_embed, a learned [N, d] parameter` |
| `sem_embed` shape | [207, 10] (embed_dim 10) |
| Rank of pre-softmax `E @ E.T` | 10 (bound 10) |
| Initialisation | torch.randn(N, embed_dim) * 0.01 (stgnn.py:239) -- random, NOT seeded from the kernel adjacency |
| **Seeded from the kernel adjacency?** | **no** |
| Pre-softmax symmetric | True |
| Post-softmax symmetric | False |
| **Directed** | **True** |
| Normalisation | row-softmax over dim=1, i.e. per SOURCE outgoing mass |
| Row sums | 1.0 to 1.0 |

**It is not initialised from the adjacency.** `sem_embed` starts at
`torch.randn(N, embed_dim) * 0.01` (`stgnn.py:239`), so `A_sem` is learned from
random init rather than as a correction to the given graph. The difference
between the two is therefore *not* the object of study: `A_sem` is its own
graph, and comparing it to the adjacency is the same kind of comparison the
explainer analysis makes.

**The directionality is an artefact of normalisation, not of learning.**
E @ E.T is symmetric by construction; the row-wise softmax breaks the symmetry, so all directionality comes from normalisation, not from a learned asymmetric similarity

**The similarity is low-rank.** `E @ E.T` has measured rank 10 with embed_dim
10, so all 42849 pairwise scores are generated by a 10-dimensional embedding.

### Effective sparsity

Structural sparsity is **zero by construction** — softmax leaves 42849 of 42849
entries strictly positive (100%). The meaningful measure is concentration:

| Measure | Value | Uniform reference |
|---|---|---|
| Row perplexity `exp(entropy)` — effective number of targets a source spreads over | mean **187.25**, median 191.01, range 124.04-207.0 | 207 |
| Mass in a row's top 8 | mean **0.0898**, median 0.0797 | 0.0386 |
| Off-diagonal pairs sitting on the ReLU floor | **19.9%** | — |

The ReLU floor is a structural quirk worth stating: `relu` maps every negative
similarity to exactly 0, and those pairs then enter the softmax at the identical
value `exp(0)`. 19.9% of off-diagonal pairs are in that state, so **the graph
does not distinguish between them at all** — they share one flat weight rather
than a range of small ones.

## 4. The alpha trajectory

`sigmoid(alpha)` is the weight on the **given** adjacency; `1 - sigmoid(alpha)`
is the weight on the **learned** semantic graph. It initialises at
`sigmoid(0) = 0.5` (`stgnn.py:240`).

| Checkpoint | Epoch | run | weight on given adjacency | weight on learned graph |
|---|---|---|---|---|
| `metr_la_best.pt` | 54 | — | 0.2968 | 0.7032 |
| `metr_la_best_epoch34_ARCHIVE.pt` | 34 | — | 0.3366 | 0.6634 |
| `metr_la_fusion_best.pt` | 39 | metr_la_fusion | 0.2788 | 0.7212 |

`CLAUDE.md` records "alpha drifted 0.49->0.39 in 3 epochs". That line comes from
the 3-epoch placeholder checkpoint, which no longer exists on disk (it was
overwritten, per the audit's 5.5). On the checkpoints that do exist the value
has moved further toward the learned graph. A dated correction has been added to
`CLAUDE.md` rather than editing the original line.

## Limitations

**This is the model's parameter, not its behaviour.** `A_sem` is one of two
supports and enters only through the `(1 - alpha)` term of the first one. A
weight in `A_sem` is not the same thing as influence on a prediction: the
adaptive support, the temporal stack, and the readout all intervene. The
explainer analysis is what speaks to behaviour; this speaks to structure.

**"Off-adjacency" still means ">3922 m by road".** The adjacency is a
thresholded Gaussian kernel on directed road distance (sigma = 2584.5 m,
kappa = 0.1), which reduces exactly to that cutoff, and most non-adjacent pairs
have no road distance recorded at all.

**Three checkpoints, not a trajectory.** Two are from the traffic-only run at
different epochs and one is a separate fusion run. This is not a per-epoch
record — the per-epoch alpha CSV for the real training run lives Colab-side
(audit 8.3) and is not on disk. Cross-checkpoint agreement here mixes epoch
drift with run-to-run variation and cannot separate them.

**Row-normalised per source.** Each source's outgoing weights sum to 1, so a
target's incoming mass is unnormalised and targets are not directly comparable
on raw incoming weight. The top-k rule is rank-based and unaffected; the
cumulative-mass rule is computed per target on unnormalised rows and should be
read with that in mind.

**Exploratory.** No prespecified analysis plan, thresholds carried over from the
explainer analysis for comparability. Nothing here is confirmatory.
